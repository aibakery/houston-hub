# Houston Hub

Luau connectors and behavior fixtures for Houston. Each bundle contains a manifest,
operations, an icon and short README/SETUP instructions for people. Agents learn
operations through `help()`. Registrations in Houston define the live catalog;
repository files are not published automatically.

Start with [AUTHORING.md](AUTHORING.md) and the
[connector skill](.agents/skills/houston-connector/SKILL.md). Follow the
[Luau guidelines](docs/luau-practices.md) for sequential, readable implementations,
small shared helpers and bounded work.

## Validation

Connector implementations and tests are Luau. Generic Go tooling in `manifest/`,
`assets/` and `tools/` validates every bundle through the same production contract.
Provider-specific assertions belong in the bundle's `tests/*.luau`; adding a
connector does not require a Go file or registration in the checker.

From a standalone Hub checkout, with `HOUSTON_RUNTIME` pointing to a matching
Houston runtime and the pinned `luau-analyze` on `PATH`:

```sh
go test -count=1 ./...
go run ./tools/validate connectors/postgres
```

Omit the path to validate every bundle, or pass an external bundle directory.
Tests use synthetic credentials and mocked provider responses. Public CI runs the
manifest and asset unit tests and the source policy in [vet.yaml](vet.yaml).
Full conformance also requires the runtime binary; runtime source extraction is
separate work. From a Houston checkout, `go -C tools/runtime run . test-connectors`
builds that runtime and checks the Hub. Publication uses the same validator.
