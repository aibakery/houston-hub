# Houston Hub

Luau connectors and behavior fixtures for Houston. Each bundle contains a manifest,
operations, an icon and short README/SETUP instructions for people. Agents learn
operations through `help()`. Registrations in Houston define the live catalog;
repository files are not published automatically.

Start with [AUTHORING.md](AUTHORING.md) and the
[connector skill](.agents/skills/houston-connector/SKILL.md). Follow the
[Luau guidelines](docs/luau-practices.md) for sequential, readable implementations,
small shared helpers and bounded work.

## Validation

Hub source is Luau (`.luau`, or Lua-compatible `.lua`). The allowlist in
[vet.yaml](vet.yaml) rejects other source languages, including Go, while permitting
manifests, Markdown, images and CI configuration. Public CI runs the pinned vet
checker; it needs no private repository or provider credentials.

Houston owns the manifest, icon, type and conformance tooling in its `connector/`
module. From a Houston checkout with this Hub revision in `hub/`:

```sh
go -C connector test -count=1 ./...
go -C tools/runtime run . test-connectors
```

The test command needs `HOUSTON_RUNTIME` pointing to the current service runtime
and the pinned `luau-analyze` on `PATH`. `test-connectors` builds the runtime and
runs every bundle; append `connectors/postgres` to select one. Houston publication
runs the same runtime checks against Luau fixtures before accepting a release.
